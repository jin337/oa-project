# OA 低代码审批系统 - 整体逻辑梳理

## 一、整体架构

```
┌─────────────────────────────────────────────────────────┐
│  前端：Vite + React + Arco Design（port 8181）           │
│  后端：Go + Gin + GORM（port 8180/api/v1）              │
│  数据库：MySQL 5.7（oa_test）                            │
└─────────────────────────────────────────────────────────┘
```

## 二、系统模块

```
系统管理（system）
├── 用户管理（用户列表 / 绑定角色 / 绑定部门）
├── 角色管理（角色列表 / 数据范围配置 / 分配菜单 / 绑定部门）
├── 菜单管理（菜单树：目录 → 页面菜单 → 按钮/权限标识）
└── 部门管理（部门树）

应用配置（application）
├── 应用列表（应用增删改查）
├── 表单元素管理（表单元素库：input/select/table/upload 等）
├── 表管理（业务表结构：字段/类型/长度）
├── 布局管理（拖拽布局：form_layout_json 存增量配置）
└── 审批流配置（流程画布：发起人 → 审批人 → 抄送人 → 条件分支）

审批管理（approval）
├── 我的发起（我提交的申请：编辑/撤回/查看详情）
├── 我的待办（我的待审批任务）
├── 经我处理（我处理过的任务）
├── 抄送我的（抄送给我的审批）
├── 草稿箱（未提交的草稿：编辑/提交/删除）
└── 审批详情（审批流程时间线 + 表单详情）
```

## 三、权限体系

### 1. 菜单权限

- 角色 → 分配菜单 → 用户绑定角色 → 前端动态路由渲染

### 2. 数据权限（闭环）

```
角色管理配置数据范围（1全部 / 2自定义部门 / 3仅本部门 / 4本部门及以下）
    ↓
用户绑定角色
    ↓
查询时自动按角色数据范围过滤（过滤字段：created_by）
```

| 数据范围     | 过滤条件                                  |
| ------------ | ----------------------------------------- |
| 全部数据     | 不过滤                                    |
| 本部门及以下 | `created_by IN (本部门+子部门所有用户ID)` |
| 本部门       | `created_by IN (本部门所有用户ID)`        |
| 仅本人       | `created_by = 当前用户ID`                 |

## 四、审批流程

### 状态机（对齐钉钉）

| 状态 | 含义                                   |
| ---- | -------------------------------------- |
| 0    | 进行中                                 |
| 1    | 已通过                                 |
| 2    | 已拒绝                                 |
| 3    | 已退回（退回给发起人，重新走完整流程） |
| 4    | 已作废                                 |
| 5    | 已撤回                                 |
| 6    | 草稿                                   |

### 审批人操作

- **同意**：通过当前节点，流转到下一节点
- **退回**：退回给发起人，发起人编辑后重新提交（重新走完整流程）
- **拒绝**：审批结束，状态变为"已拒绝"

## 五、动态表单引擎

### 取值表达式约定

| 前缀       | 含义           | 用途                       |
| ---------- | -------------- | -------------------------- |
| `form.xxx` | 整个表单的值   | 数据源参数、联动映射       |
| `item.xxx` | 当前选中项的值 | select/treeSelect 的选中项 |
| 无前缀     | 接口响应根节点 | target_mapping 的 source   |
| `${}`      | 字符串拼接     | url/label 拼接             |

### 核心配置

- **data_source**：动态数据源（type=api 时请求接口加载选项）
- **actions**：事件联动（on_mount/on_change/on_blur 触发 set_value 或 fetch_and_fill）
- **dynamic_states**：动态显隐/禁用（visible_if / disabled_if）
- **default_value**：默认值
- **validation_rule**：校验规则
- **columns**：子表列配置（和 elements 一样解析）
- **公共计算/转换接口`POST /utils/calculate`支持的类型**:
  - **`number_to_upper`** - 数字转大写金额
    - 请求示例：`{ "type": "number_to_upper", "value": 100000 }`
    - 返回示例：`{ "result": "壹拾万元整" }`
  - **`calc`** - 表达式计算（支持加减乘除取模和括号）
    - 请求示例：`{ "type": "calc", "value": "(100+2)*3 % 7" }`
    - 返回示例：`{ "result": 5 }`
    - 支持的运算：`+`、`-`、`*`、`/`、`%`、`()`
    - 支持小数、负数、空格自动忽略

## 六、站内通知

### 实时推送（SSE）

- 后端 `notification_hub.go` 管理用户 SSE 连接
- 审批任务流转时自动生成通知
- 前端 `NotificationBell` 通过 EventSource 实时接收

### 通知类型

| type | 含义 | 接收人 |
| ---- | ---- | ------ |
| 1    | 待办 | 审批人 |
| 2    | 退回 | 发起人 |
| 3    | 抄送 | 抄送人 |
| 4    | 结果 | 发起人 |

### 其他

- 已读通知自动过滤
- 已读超 30 天自动清理
- 通知按今天/昨天/更早分组
- 多标签页同步（BroadcastChannel）

## 七、文件上传

- 后端：`POST /api/v1/upload?app_code=xxx`，单文件上传
- 存储：`back-end/uploads/{app_code}/{时间戳}.{ext}`
- 返回：`{ url, name, size }`
- 业务表字段类型：json（自动序列化/反序列化）

## 八、关键设计决策

1. **布局管理只存增量**：其他属性从表单元素管理读取合并，改元素设置无需回布局重拖
2. **数据权限闭环在角色管理**：应用配置不再重复配置数据权限
3. **退回对齐钉钉**：退回给发起人后重新走完整流程（新旧任务不叠加）
